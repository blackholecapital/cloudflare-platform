Imports are explicit operator requests with allowlisted source/table mapping. Missing bindings/tables return a diagnostic without creation. Keyset checkpoints represent a bounded snapshot traversal, not continuing live synchronization; later rollout must choose a frozen source range/rescan strategy for new lexically earlier IDs. Unique source references prevent duplication. No imported paid label creates verified payment/access. Unclaimed legacy ownership needs a secure later claim process. Changing code does not erase imported provenance.

## Rollback and remaining lifecycle work

Code rollback is separate from retained data. Additive saas_* tables/mappings are retained and never dropped by rollback. New order snapshot/review/configuration records are immutable; no destructive reverse migration is supplied. Returning to an old anonymous checkout worker would restore the exposure, so security rollback requires coordinated service unavailability rather than bypassing authentication.

Pass 2 must establish authenticated payment evidence, stable subscription/billing-start authority, merchant separation, outbox/event delivery and race-safe lifecycle processing. Current Checkout KV does not implement a durable cross-system event ledger. Invoice/subscription events cannot be interpreted as checkout sessions. Lead/PayMe legacy create paths do not gain the full configured-order recovery lifecycle merely by adding signatures. Existing manual legacy notifications/manifests are preserved; canonical white-glove handoffs use the revised shared-tenant contract. Product adapters/tenancy hardening, invitation/claim UX, downloads and full customer/operator portals remain later work.
